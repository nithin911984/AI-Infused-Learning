# MCP Cricket Demo

This project demonstrates a small Model Context Protocol (MCP) setup using Python. It includes an MCP server, a client that calls the server directly, an LLM-powered agent that selects tools, and a small evaluation suite.

All cricket scores and player statistics in this project are fictional. No external cricket-data API is called.

## What you will learn

By working through the scripts in order, you will see how to:

1. Start an MCP server over the standard input/output (`stdio`) transport.
2. Connect an MCP client and complete the initialization handshake.
3. Discover the tools exposed by an MCP server.
4. Call an MCP tool directly without using an LLM.
5. Allow an LLM to select a tool and provide its arguments.
6. Return tool results to the LLM to produce a final answer.
7. Evaluate whether an agent selected the expected tool and returned the expected information.

## Project files

| File | Purpose | API key required |
| --- | --- | --- |
| `cricket_server.py` | Exposes `get_live_score` and `get_player_stats` as MCP tools | No |
| `step1_client.py` | Connects to the server, lists its tools, and calls one directly | No |
| `step2_agent.py` | Uses an LLM to decide which MCP tool to call | Yes |
| `step3_evals.py` | Runs five evaluation cases against the agent | Yes |
| `requirements.txt` | Lists the required Python packages | No |

The client scripts start `cricket_server.py` automatically as a child process. You do not need to start the server separately.

## Requirements

- Python 3.10 or newer
- A terminal or command prompt
- A Groq API key for Steps 2 and 3

This project currently uses version 1 of the MCP Python SDK, as specified by `mcp<2` in `requirements.txt`.

## 1. Create a virtual environment

### macOS or Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Windows PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

When the environment is active, your terminal will usually show `(.venv)` before the prompt.

## 2. Install the dependencies

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

## 3. Run the direct MCP client

The first script demonstrates MCP without an LLM or API key:

```bash
python step1_client.py
```

The output should show:

- A completed MCP initialization handshake
- The two tools exposed by the server
- The input schema for each tool
- The fictional result returned by `get_live_score`

## 4. Configure the Groq API key

Create a local `.env` file from the included example:

### macOS or Linux

```bash
cp .env.example .env
```

### Windows PowerShell

```powershell
Copy-Item .env.example .env
```

Open `.env` and replace the placeholder with your Groq API key:

```text
GROQ_API_KEY=gsk_your_key_here
```

You can create a key at [Groq Console](https://console.groq.com/keys).

Do not commit `.env` or share your API key. Each learner should use their own key.

## 5. Compare the agent with and without MCP tools

First, ask the model a live-score question without providing MCP tools:

```bash
python step2_agent.py --no-tools "What is the live score of India vs West Indies?"
```

Then ask the same question with MCP tools enabled:

```bash
python step2_agent.py "What is the live score of India vs West Indies?"
```

With tools enabled, the output shows:

1. The tool selected by the model.
2. The arguments generated by the model.
3. The data returned by the MCP server.
4. The model's final answer.

Try a player-statistics question as well:

```bash
python step2_agent.py "How many runs has Shubman Gill scored this series?"
```

## 6. Run the evaluations

```bash
python step3_evals.py
```

The evaluation script checks both:

- Whether the model selected the expected tool
- Whether the final answer contains the expected fact

LLM output can vary between runs, even when the temperature is set to zero. The evaluation suite also makes multiple API requests and is subject to your Groq account's limits.

## Using a different model

The default model is `openai/gpt-oss-20b`. To use another Groq model that supports tool use, set `DEMO_MODEL` before running the agent.

### macOS or Linux

```bash
export DEMO_MODEL="your-model-id"
```

### Windows PowerShell

```powershell
$env:DEMO_MODEL="your-model-id"
```

## Troubleshooting

### `GROQ_API_KEY is not set`

Confirm that `.env` exists in the same folder as `step2_agent.py` and contains a valid key without extra spaces.

### `ModuleNotFoundError`

Activate `.venv` and install the dependencies again:

```bash
python -m pip install -r requirements.txt
```

### PowerShell blocks virtual-environment activation

Run the following command for the current PowerShell session, then activate `.venv` again:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

### The model attempts to call an unavailable tool

Run the command again. Model-generated tool calls can occasionally vary. You can also set `DEMO_MODEL` to another Groq model that supports tool use.

### The evaluation score changes between runs

The evaluations exercise an LLM rather than deterministic application logic. Occasional variation is expected.

## Deactivate the virtual environment

When you are finished:

```bash
deactivate
```
